### Выбор ресурсов и их параметры

| Ресурс Terraform | Назначение | Обоснование выбора параметров |
| :--- | :--- | :--- |
| **`yandex_vpc_network`** | Виртуальная частная сеть (VPC) | Создает изолированное сетевое пространство для всех ресурсов проекта, что является стандартом для безопасности и управления. |
| **`yandex_vpc_subnet`** (public) | Публичная подсеть | Размещает ресурсы, которым нужен прямой доступ из интернета (например, веб-серверы, балансировщики). Доступ обеспечивается через NAT. |
| **`yandex_vpc_subnet`** (private) | Приватная подсеть | Используется для внутренних ресурсов (базы данных, бэкенд-сервисы), которым не нужен прямой доступ извне. Это ключевой элемент для повышения безопасности инфраструктуры . |
| **`yandex_vpc_gateway`** | NAT-шлюз | Позволяет ресурсам из приватной подсети инициировать исходящие соединения в интернет (например, для скачивания обновлений), но блокирует входящие подключения, что защищает внутренние компоненты. |
| **`yandex_vpc_route_table`** | Таблица маршрутизации | Направляет весь исходящий трафик (`0.0.0.0/0`) из приватной подсети через NAT-шлюз, реализуя схему безопасного доступа в интернет. |
| **`yandex_compute_instance`** | Виртуальная машина | Основной вычислительный ресурс. |
| **`yandex_compute_disk`** (boot) | Загрузочный диск (15 GB, `network-ssd`) | 15 ГБ достаточно для ОС и системных утилит. Тип `network-ssd` обеспечивает хороший баланс между производительностью и стоимостью для системного диска . |
| **`yandex_compute_disk`** (secondary) | Диск для данных (20 GB, `network-hdd`) | Выделение отдельного диска для данных позволяет управлять ими независимо от ВМ. Тип `network-hdd` выбран как экономичное решение для хранения данных, не требующих высокой скорости доступа. |
| **`yandex_vpc_security_group`** | Группа безопасности | Реализует модель брандмауэра "запрещено все, что не разрешено". **Правила `ingress`** открывают только необходимые порты (22 для SSH, 80 для HTTP), ограничивая поверхность атаки. |
| **`yandex_storage_bucket`** | Бакет в Object Storage | Предназначен для хранения неструктурированных данных (логов, бэкапов, статики). Масштабируемое и экономически эффективное решение для хранения больших объемов информации . |
| **`random_id`** | Генератор случайных ID | Используется для добавления случайного суффикса к имени бакета, что гарантирует его глобальную уникальность в Yandex Cloud, как того требует сервис Object Storage. |

### Плюсы декларативного подхода и Infrastructure as Code (IaC)

> Простота — главное преимущество этого подхода. Не нужно описывать шаги для получения нужной конфигурации, уменьшается и риск сделать ошибку в написании настройки. 

1.  **Воспроизводимость:** Любой член команды, имея доступ к коду, может развернуть **точную копию** инфраструктуры за минуты.   инфраструктура  может быть индетично развернута в разных окружениях  в dev, staging, prod

2.  **Масштабируемость:** Если нам понадобится не одна, а десять одинаковых ВМ, нам не нужно повторять ручные операции десять раз. Достаточно добавить в код `count = 10`. Если нам нужно изменить размер всех ВМ, мы меняем значение одной переменной (`var.vm_cores`) и запускаем `terraform apply`. Инфраструктура становится гибкой, как программный код, и может расти вместе с ростом бизнеса без кратного увеличения трудозатрат.

3. **Версионность**: Изменения отслеживаются в Git, возможен rollback

4. **Документация**: Код служит живой документацией текущего состояния
